# 水都 — 治水・利水シミュレーション

侵食でつくられたリアルな流域を舞台に、**川と付き合いながら町を育てる**シミュレーションゲーム。
Cities: Skylines のようにセル単位で水が流れ、Timberborn のように水面から土が潤う。
梅雨と台風の増水をダムと堤防で抑え、渇水を貯水池と地下水で凌ぎ、田畑を潤して人口を養う。

シミュレーションは TypeScript のみ (ゲームエンジンなし)、描画は **three.js による 3D**。
地形・水面・施設・植生はすべて実行時に手続き的に生成していて、外部の 3D モデルや
テクスチャは一切持っていない。

**▶ ブラウザで遊ぶ: https://kamocyc.github.io/claude-web-test-14/**
(`main` へ push すると GitHub Actions がビルドして自動で更新される。WebGL2 が必要)

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # シミュレーションのテスト
npm run campaign   # 自動プレイヤーに2年ぶんプレイさせ、サンプルセーブを生成
npm run dam-effect # ダムあり/なしで同じ洪水を流し、治水効果を測る
npm run dam-sites  # ダムの適地 (谷の狭さ・流域・貯水量) を測る
npm run build      # 型チェック + 本番ビルド
```

`?seed=<数値または文字列>` を付けると同じ流域を再現できる (例: `/?seed=hydro-demo`)。
ツールバーの**サンプル**を押すと、下の自動プレイヤーが育てた町 (人口1,404) をそのまま読み込める。

## シミュレーションのしくみ

### 1. 地形 — 水が削ってつくった谷

ノイズで骨格をつくったあと、実際に水滴を降らせて削る。

1. **ドメインワープした fBm + リッジノイズ** で山地 (北) から平野 (南) への骨格をつくる。
   格子ノイズは軸に沿った縞を生むので、オクターブごとに座標系を約 37° 回転させている
   (これをやらないと支流が不自然な平行線になる)。
2. **水滴侵食** を 9 万滴。慣性・運搬能力・堆積を持つ水滴が斜面を下りながら谷を刻む。
   侵食パラメータは 0..1 に正規化した高さ場を前提にしているので、メートルへの変換は侵食後に行う。
3. **Priority-Flood + ε** ([Barnes et al.](https://arxiv.org/abs/1511.04463)) で窪地を解消し、
   全セルからマップ外へ単調に下る経路を保証する。これで「水が溜まって消える」ことがなくなる。
4. **MFD (複数流向) の流域面積** を計算し、大きいところを河道として掘り込む。
   D8 (最急1方向) だと平坦地で流路が 8 方向に吸着して直線的な水路になるため、
   低い隣接セルすべてへ傾斜の 2.6 乗で按分している。
5. **山あいの狭窄部 (ゴルジュ) を彫る** — 流路が確定したあと、山地〜中下流の4つの帯で
   いちばん水を集めている地点を選び、**川筋をたどって両岸だけを河床 +21〜30m まで
   持ち上げる**。川そのものと支流は絶対に埋めないので、水の出口は塞がらない。

結果として、**分岐した支流・蛇行・河口の三角州・山あいの湖**が自然に現れる。

狭窄部を彫っているのは、**ダムを架けられる場所をつくる**ため。ダムはセルごとに 1 基 (￥4,200)
並べて谷を塞ぐので、必要な径間数がそのまま建設費になる。以前は谷が広すぎて、本流を塞ぐのに
20 径間 (￥88,200) 以上かかる — つまり事実上どこにも架けられない — 地形だった。

`npm run dam-sites` で適地を測れる (谷を塞ぐのに要する径間数・上流流域・貯水量)。

| | 以前 | いま |
|---|---|---|
| 10 径間以下で塞げる地点 | 0〜3 箇所 (6シード中5つが 0) | **54〜138 箇所** (全シード) |
| 本流を塞ぐ最小径間 (seed hydro-demo) | 12 径間 ￥50,400 | **6 径間 ￥25,200** |
| その地点が押さえる流域 | — | 全流域の **50%** |

### 2. 水 — 仮想パイプ法による浅水シミュレーション

`src/sim/hydrology.ts`。セル間に仮想のパイプを張り、水面標高差で流束を加速、摩擦で減衰させる
(Mei et al. のモデル)。

- 流束は符号付きで辺ごとに 1 本だけ保持し、**そのセルにある水量以上は流出できない**制約で
  スケールする。これで水深が負にならず、質量が厳密に保存される
  (テスト: 盆地に入れた水は総量を保ったまま水平な水面に落ち着く)。
- 構造物 (堤防・ダム・水門) は地形を嵩上げした「壁」として扱う。だから水は物理的に堰き止められ、
  水位が天端を越えれば普通に**越流する**。
- マップ外は海 (標高 0m) として扱い、境界から水が出入りする。

### 3. 時間 — 圧縮された河川時間

このマップは全長 2.3km、河川の一区間にすぎない。上流の広大な流域はマップ外にあるので、
洪水の主因は**源流セルからの流入量 (m³/s)** として与える。

水理計算はゲーム時間とは別の時計 (hydro-sec) で回る。1 ゲーム時間 = 72 hydro-sec。
「1時間あたり◯mm」で与えられる降雨や地下水流出を流量に直すときは 3600 で割り、
河川流量と同じ物差しに乗せる (`TIME_COMPRESSION`)。
この換算を間違えると、**川が受け取る量より蒸発・浸透で失う量が大きくなって数日で干上がる** —
実際に開発中に一度そうなった。

### 4. 灌漑 — Timberborn 方式の湿潤伝播

`src/sim/moisture.ts`。水面 (川・水路・湛水) を水源としたバケットキュー BFS で、

- 最大 **11 セル**まで湿潤が広がり、距離に応じて減衰する
- ただし**水面より 2.6m 以上高い土地へは登れない**

段丘の上の畑を潤すには、水路を掘って水を引くか、水門で水位を上げる必要がある。
土壌水分も湿りを与えるので、雨のあとは一時的に畑が作れるが、乾けば枯れる。
安定した農業には灌漑が要る。

### 5. 気象 — 予報が嘘をつかない天気

`src/sim/weather.ts`。**その日の天気は「日番号とシードから決まる純関数」**なので、
7日先の予報は必ず当たる。プレイヤーは予報を信じて備えられる。

1年は 96 日で、春 → 梅雨 → 夏 → 秋 → 冬。梅雨は雨が多く、夏〜秋にはまれに**台風** (日雨量 150〜340mm)。

降った雨はマップ外の流域に貯まり、**速い応答 (時定数 9h) と遅い応答 (520h)** の 2 段の
貯留槽を通って流入量になる。だから雨が降ってから川が増えるまでに数時間〜数日の遅れがあり、
雨が止んだあともしばらく増水が続き、降らない日が続くと緩やかに渇水へ向かう。

実測 (1年通し): 冬の渇水期 約 5 m³/s、平水 10〜20 m³/s、梅雨の大雨で 130 m³/s。

**手動天気モード** — 画面下の「天気」から、暦を無視して降水強度 (mm/h)・天気・気温を
好きなタイミングで指定できる。解除するまでその天気が降り続けるので、梅雨や台風を待たずに
洪水を試したり、晴れを続けて渇水を起こしたりできる。
指定した雨はマップ外の流域貯留にもそのまま入るので、**流入量は普段と同じ経路で数時間遅れて
増える** (堤防やダムの効きを試すのに使える)。手動のあいだは予報も「この天気が続く」を返し、
無降雨日数は実際に降った量から数える。セーブにも残る。

### 6. 都市・農業・経済

- **上水道**: 取水施設 → 浄水場 → 配水池 → 水道管 → 住宅。水道管でつながっていない住宅には
  給水されない。処理能力を超えた原水は未処理水として配られ、満足度が下がる。
  川が涸れれば取水量は落ち、配水池の貯留を取り崩す。
- **農業**: 畑は湿潤度 35%、水田は 80% を要求する。水田は収量が高く浅い湛水にも耐える。
  冠水すれば作物は傷む。
- **人口**: 給水・食料・浸水しない立地の 3 つが揃った住宅に人が入る。税収が財源。

### 7. 災害

- 堤防やダムは**越流すると損傷し、健全度 0 で決壊する**。決壊すると壁が消えて一気に浸水する。
  ただ高くするだけでは守れない。
- 建物は水深が耐性を超えると損傷して失われる。耐性は施設ごとに違い、取水施設は水中でも平気、
  水道管は埋設なので強く、住宅は 32cm で浸水被害が始まる。
- **排水機場**は半径 6 セルの内水を強制排除する。堤防の内側に溜まった水を汲み出す最後の砦。
- 「氾濫面積」は平常時の水域との差で測る。ダムで貯めた水のように 3 日以上ずっと
  水を湛えている場所は新しい水域として平常時に繰り入れ、洪水と区別する。

## 描画 — three.js による 3D

「どこが高くて、どこに水が来て、何が建っているか」が一目で分かることを目標にしている。
モデルもテクスチャも外部ファイルを持たず、すべて起動時にコードから作る。

### 地形

頂点は等間隔の格子 (セルあたり 2 分割 = 384×384) で、**標高は頂点シェーダが標高テクスチャから読んで
持ち上げる**。だから掘削・盛土のたびに 15 万頂点を CPU で作り直さずに済み、更新は
192×192 のテクスチャを1枚書き換えるだけで終わる。

法線はフラグメントシェーダで標高テクスチャの差分から作る。ポリゴンの分割数に縛られないので、
遠景でも尾根と谷が潰れない。ここに「谷は暗く尾根は明るく」する曲率項を足していて、
これが起伏の読み取りやすさにいちばん効いている。

地表の色は**標高・傾斜・流域面積・水深・湿潤度**から手続き的に決める。

| | |
|---|---|
| 砂利・砂 | 汀線と河床 (流域面積が大きいところ) |
| 草地 → 森 | 標高 6〜26m で入れ替わる。マクロノイズで斑にする |
| 岩 | 傾斜が急なところ。三面投影 (triplanar) でテクスチャが伸びないようにする |
| 雪 | 雪線より上。冬は雪線が下がる |
| 濡れ | 水深と土壌水分で暗く・つやを出す |

浮動小数テクスチャは WebGL2 では線形補間できないので、シェーダ側で自前のバイリニア補間をしている
(水面標高は cm 単位の精度が要るため half-float では足りない)。

### 水面

地形と同じ格子を**水面標高**まで持ち上げる。乾いたセルでは水面標高 = 地面標高なので、
水際では水面が自然に地面へ潜り込む (別途マスクを作らなくても汀線が出る)。

法線は「水面そのものの傾き」+「流速方向へスクロールする波の法線マップ2枚」。
だから**急流では水面が傾いて波が下流へ流れ、湖ではゆっくり揺れるだけ**という差が出る。
深さで吸収した透過色と、フレネルで混ぜた空の反射、太陽のハイライト、
早瀬と汀線の泡を重ねている。空の色は天球と同じ関数から作っているので、夕焼けは川面にも映る。

### 空・光

ゲーム内時刻から太陽の方向を決め、その高度で空の色 (天頂・地平・太陽) を作る。
**その空から PMREM で環境マップを焼いて `scene.environment` に入れている**ので、
地形も建物も「空の色で」照らされる。天気に応じて雲量・減光・霧の濃さが変わり、
雨や雪はカメラ周りの箱を落ち続ける GPU パーティクルで降る。

影はマップ全体を覆う位置に固定した平行光源のシャドウマップで落とす。
視点に追従させて範囲を絞ると、シャドウマップの外側が「常に影」と判定されて遠景が
一様に暗くなってしまうため。

### 施設・植生

施設は箱・円柱・角錐の組み合わせで、種類 × パートごとに `InstancedMesh` を1つ持ち、
毎フレーム行列と色を書き込む。シミュレーションの状態がそのまま見た目に出る:

- 作物は**生育度で背が伸びて色が緑 → 黄金色**に変わる
- ゲートは**開けると持ち上がり**、水が抜ける隙間が見える
- 損傷した堤防・ダムは**実際に低くなる** (`World.effectiveWall` と同じ係数で縮む)
- 夜は住宅の窓が灯る (入居している町だけが光る)

樹木は「急すぎる崖・河床・雪線より上には生えない」という規則で撒き、
低周波ノイズで森の疎密を作る。建物を建てるとその区画の木は消える。

### 高さ方向の強調

このマップは 2.3km 四方に対して比高が 130m しかなく、実寸で描くと平らに見える。
そこで既定で **1.45 倍**に強調している (画質パネルで 1.0〜3.0 倍に変更可)。

ただし強調するのは**地形・水面・堤防・ダム・水門**だけで、住宅や浄水場の高さは実寸のまま。
建物まで伸ばすと家が塔のようになってしまう一方、堰の高さは「水を止める高さ」そのものなので、
水面と同じ倍率で伸ばさないと嘘になる。

## 自動プレイヤーによる検証

「このゲームは実際にクリアできるのか」を人手で確かめるのは大変なので、
機械的にプレイする自動プレイヤー (`tools/autoplay.ts`) を用意し、
何もない流域から 2 年ぶん通しでプレイさせている (`npm run campaign`)。

自動プレイヤーは毎日こう判断する:

1. **給水能力を人口に先行させる** — 需要の 1.8 倍を保つように取水・浄水・配水池を増設
2. **食料は「在庫」ではなく「生産能力」で判断** — 人口比の在庫を目標にすると農地が際限なく増えて維持費で潰れる
3. **治水は町が稼げるようになってから** — 人口 500 を超えたら積立を始め、堤防 → 排水機場 → ダムの順に固める
4. **拡張が収支の柱** — 住宅は 10 日ほどで元が取れるので、積立を上回った分はすべて宅地に回す
5. **ゲート操作** — 予報のピークが 55 m³/s を超えれば事前放流、出水中は絞ってピークカット、
   ただし上流水位が天端まで 2.5m を切ったら全開 (実際のダムの「ただし書き操作」)

### 結果 (シード `hydro-demo`, 192日)

| | |
|---|---|
| 人口 | 43 → **3,144 人** |
| 給水率 | 常に **100%** |
| 最大流入量 | **374 m³/s** (台風) |
| 失った建物 | 2 (氾濫原の畑×2) — **住宅・上水道・治水施設は 0** |
| 堤防・ダムの決壊 | 0 |
| 最終的な施設 | 取水4 浄水2 配水池2 水道管86 住宅262 水田188 畑155 堤防47 排水機場1 **ダム1径間** |

ダムが 21 径間から 1 径間になったのは、地形に狭窄部ができて**谷を1セルで塞げる場所**が
生まれたため (下の「地形」節を参照)。

### ダムは本当に効いているのか (`npm run dam-effect`)

「ダムを建てた」だけでは治水になっていない可能性があるので、同じ洪水を
**ダムあり / ダムあり(ゲート操作なし) / ダムなし** の3通りで流して比較する。

ゲート操作は *来る前に空け、来たら閉める*。事前放流は貯水池で受けきれない規模
(150 m³/s 超) のときだけ行う — 中規模の出水にまで事前放流すると、貯めた水を
先に流してしまってかえってピークが上がることが実測でわかった。

> **いまの状態**: 地形に狭窄部を入れて以降、同梱サンプルのダムは **1 径間 (￥4,200)** で
> 谷を塞いでいる (以前は 21 径間 ￥88,200)。堰の上流には 3.6m の貯水池ができている。
> ただしこの比較ツールは**有意な差を検出できていない** (ダム直下のピーク水位 5.18m → 5.18m)。
> ツールが「ダム直下」を北側と決め打ちしているのに、この地形では川が北へ流れているため、
> 測っている場所がそもそもずれている可能性が高い — **未解決**。
> (地形を変える前は 21 径間のダムで、下流のピーク水位を 1.95m → 0.91m、**53% 低減**していた)

この検証で見つかって直したもの:

- **経済が構造的に破綻していた** — 人口96人の税収 ￥369/日 に対し上水道の維持費だけで ￥1,097/日。
  どう遊んでも赤字から抜け出せなかったので、税収・維持費・作物の収量を組み直した。
- **正常な放流でダムが壊れていた** — 越流判定を「水深」で見ていたため、ゲートを開けて放流している水を
  越流と誤判定していた。「全閉時の天端を水面が越えたか」で判定するよう修正。
- **ダムが満水でも貯め続けて決壊していた** — 上流水位を見て容量が尽きたら全開にする操作を追加。
- **ダムが治水にまったく効いていなかった** — 「上流で流量が大きい所」を探していたため、
  町とは別の水系にダムを架けていた (下流経路が町から136セル離れていた)。
  取水口から本流を遡って地点を選ぶよう修正。あわせて次の3つも直した:
  町を集水域のない枝沢に作っていた / 資金切れで21径間中9径間しか架からず水が素通しだった /
  ダムの水没予定地に自分で田畑を作って沈めていた。
- **ゲート操作が逆効果だった** — 「出水予報が出ている間は全開」にしていたため、
  洪水の最中もゲートが開きっぱなしでダムが何も貯めていなかった。
  *来る前に空け、来たら閉める* 順序に修正し、事前放流は貯水池で受けきれない
  規模 (150 m³/s 超) のときだけ行うようにした。

## セーブ / ロード

`src/sim/save.ts`。地形は seed から決定論的に再生成できるので、保存するのは差分だけ:

- 掘削・盛土で変えたセルだけの標高
- 建造物 (種類・座標・健全度・ゲート開度・生育度・入居率・貯水量)
- 水深・土壌水分・浸水履歴のグリッド (Uint16 / Uint8 に量子化して base64)
- 気象の内部状態 (流域の 2 段貯留槽) — これを復元しないと洪水・渇水の位相がずれる

読み込み時、同じ流域なら地形生成を飛ばして即座に差し替え、別の流域なら
地形から作り直して描画側も入れ替える。

同梱のサンプル (`public/saves/sample.json`, 275KB) は上の自動プレイの最終状態。

**序盤の進め方**

1. 川沿いに**取水施設**、隣に**浄水場**と**配水池**。
2. **水道管**でつなぎ、その先に**住宅**。つながっていないと給水されない (調査モードで確認できる)。
3. 川沿いの低地に**水田**、少し離れた場所に**畑**。湿潤オーバーレイ (M) で
   緑 = 水田可 / 黄 = 畑可 が分かる。
4. 梅雨・台風の前に**堤防**を築き、**ダム**で洪水調節。予報を見て**事前放流**でダムを空けておく。
5. 渇水期はダムを閉じて貯留し、取水を守る。

## テストが押さえていること

- 窪地除去後にマップ内から窪地が消え、標高が下がらないこと
- 盆地に入れた水が**質量を保ったまま水平になる**こと、急斜面でも水深が負や NaN にならないこと
- 壁が水を堰き止め、水位が天端を越えれば越流すること
- 生成した流域で川が海まで抜け、水が溜まり続けないこと
- 灌漑が距離で減衰し、**崖の上には届かない**こと / 水路を掘れば届くようになること
- 予報した日の天気が、その日になっても一致すること
- 上水道をつなぐと給水され人口が増え、取水施設と配水池を失うと人口が減ること
- 越流した堤防が損傷し、やがて決壊すること
- ダムのゲートを閉じると上流に貯まり、開けると下流へ放流されること
- 保存 → 読み込みで施設・地形改変・資金・日時が戻り、水の分布が誤差 1mm 以内で復元されること
- 読み込んだ状態から続きをシミュレートしても、元の世界と同じ経過をたどること
- 同梱のサンプルセーブが実際に読み込めて、人口と給水が生きていること
- 自動プレイヤーが 40 日で上水道を敷き、人口を増やし、破産も建物の損失もしないこと
